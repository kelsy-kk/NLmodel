## 2026-10-21（上午）v0.1 初稿

## 2026-10-21

### 已确认的事实（来自现有代码与用户说明）

1. 用户明确：模型不是单表，而是「由多个表组成的一个组，它们在一起圈定一个业务场景」。因此术语实际有四个载体：模型、模型内的表、表字段、模型内的指标。
2. 现有实现核对结果：
   - 字段级术语已支持，存储 `biz-modeling-field-terms-v1`，键为「模型名|字段英文名」；自动匹配为同名/同义词精确匹配 + 描述相似推荐。
   - 指标级术语已支持，`metric.termIds` 数组；入口为工具栏批量挂载 + 指标编辑表单选择器。
   - 模型级**无真实挂载**。`term.modelNames` 是术语的生效模型（作用域），模型头「关联术语」按钮实际执行 `autoLinkTermsForCurrentModel`（批量给字段挂）。
   - 表层**无术语概念**。
   - 术语详情反查只有字段、指标两组，缺模型与表。
3. 用户关注点：术语挂在字段/表/指标上会不会冲突。已确认 OpenMetadata 默认不做语义冲突校验，原型需要自己补护栏。

### 本次形成的设计结论

1. **术语分七类（measure / dimension / time / entity / fact / condition / metric-def），类型决定可挂层级**，类型与层级不匹配时硬拦。这是解决「随意挂」的根本约束。
2. 术语卡扩展为九组字段，问数能否用对取决于「计算规格 / 时间口径 / 限定条件 / 值域 / 示例问法」五组。
3. **挂载即配置**：挂载记录必须携带 `spec`（agg、unit、precision、taxIncluded、timeField、predefinedFilter），因为同一字段在不同场景用法不同。规格属于挂载关系，不属于术语本体。
4. 目标标识必须带模型名前缀：`field:模型名|表名|字段英文名`，解决现键「模型名|字段名」在多表同名字段下互相覆盖的问题。
5. **继承规则**：模型层术语只向下继承语境，不继承口径定义。字段无 primary 术语时不向上兜底，直接标记为不可问数。
6. 校验分三档：红（类型不匹配、主术语唯一、互斥组、作用域）/ 黄（指标口径不一致、层级越界、跨模型同表不一致）/ 灰（同义词重复、重复挂载）。
7. `predefinedFilter` 与 `valueMapping` 一律结构化存储，不存裸 SQL 字符串。
8. 建设顺序改为「问数日志驱动」（top 问句 → 字段被问频次 → 头部 20% 字段覆盖 80% 问句），不做全量挂载。
