术语体系与挂载设计（面向问数赋能）

文档状态：设计稿，待评审。文中标注「建议」的规则尚未经业务确认；标注「现有」的内容依据当前 index_v2.0.html、term-module.js、metric-module.js 的实际实现整理。

版本：v0.2（2026-10-21）新增第 3 章「智能问数查询链路」，明确五类绑定（模型/对象/字段/指标/维度）在问数引擎中的消费方式；v0.1 初稿。

适用范围：数据平台 → 建模中心 → 语义模型（术语中心 / 结构语义 / 指标）。不覆盖问数引擎的改词、SQL 生成与执行。

前置依赖：模型为「业务场景组」，由一个或多个物理表经 Join 组成，表下含字段，场景下含指标。术语需同时服务治理与问数两类消费方。

1. 需求概述

1.1 背景与现状

当前术语能力已覆盖两类载体，但口径分散、互不校验：

载体现有实现缺失
字段已支持手动挂载与自动匹配（同名/同义词精确匹配 + 描述相似推荐），存储于 biz-modeling-field-terms-v1，键为「模型名|字段英文名」只有挂载关系，没有计算规格；键不含表层，多表同名字段会撞键
指标已支持 metric.termIds 数组，入口为工具栏批量挂载与指标编辑表单选择器与字段术语无任何交叉校验，指标口径与来源字段可能矛盾
模型无真实挂载。term.modelNames 仅为术语的「生效模型」作用域；模型头「关联术语」按钮实际执行的是批量给字段挂载场景级语义缺位，问数无法按业务场景路由
表无术语概念Join 选边与事实/维表判断缺少语义依据

1.2 问题：问数在四个位置必然出错

问数需要把用户说出的业务词稳定映射为「字段 + 聚合 + 过滤」。当前术语只提供名称与定义，缺少可执行规格，因此以下四类失败必然发生，且无法从数据侧自愈：

失败模式典型问句后果
聚合方式靠猜「合同额多少」该 SUM 却 COUNT，或对已汇总字段二次求和
时间列选错「上个月合同额」签订日期与确收月份混用，两值可差数十个百分点
隐含条件丢失「有效合同额」未附加 status 过滤，把作废、草稿一并计入
跨表口径不一致「收入达成率」指标挂「目标额」，公式实际引用「合同额」，指标与字段口径长期矛盾且无人发现

编号目标衡量方式状态

1.4 角色与范围

角色：数据建模师（挂载与规格填写主体）、业务专家（术语定义与同义词维护）、问数使用者（间接受益，通过命中率体现）、数据治理管理员（互斥组与冲突处置）。

本次范围：术语卡的字段扩展、四层挂载模型、挂载规格、一致性校验、就绪度与覆盖率度量、相关页面改造点。

不在本次范围：问数引擎的意图识别与 SQL 生成、术语审批流（沿用现有上线流程）、数据源元数据自动同步、术语关系图谱改版。

2. 核心设计

2.1 术语分类型，类型决定可挂层级

这是本方案的基础约束：术语不是同质的标签，不同类型承载不同语义，只能挂到与之匹配的层级。 这一条解决了「术语可以随意挂」导致的层级污染，也把挂载从「打标签」变成「配置语义」。

术语类型 termType含义允许挂载层级类型必填规格
度量 measure可聚合的数值口径字段（必须）、指标聚合方式、单位、精度、默认时间口径
维度 dimension分组依据，有值域字段（必须）、指标（限定维度）值域映射（枚举已知时）
时间 time时间口径与粒度字段（必须）时间粒度、时间角色
实体 entity业务对象，如合同、项目、供应商模型（必须）、表（必须）—
事实 fact业务事件或流水，有粒度表（必须）、模型（辅助）粒度声明
条件 condition限定修饰，如「有效」「含税」「在建」字段（作为规格过滤条件引用）、指标结构化过滤条件
指标口径 metric-def派生指标，带公式指标（必须）公式与聚合

规则：类型与层级不匹配时硬拦，按钮置灰并写明原因（如「实体类术语不能挂在字段上，请改挂到模型或表」）。该映射表作为唯一权威口径，前端校验与后端校验共用。

2.2 术语卡字段

现有术语卡具备名称、定义、同义词、生效模型、上线状态。现按「可执行」目标扩展为九组，全部字段如下。问数能否用对，取决于第 3 至第 7 组是否存在。

分组字段类型必填规则与示例
1 标识 termId字符串是 全局唯一，系统生成，创建后不变。挂载关系只引用 termId，不引用名称或 FQN，避免改名断链
name字符串，≤30 字是术语库内唯一，FQN = 库名.术语名。重名在同库内直接拒绝，跨库同名允许但触发软提示
synonyms字符串数组，≤20 项是用户真实说法，用于问数召回。如「合同额」的 synonyms：合同金额、签约额、合同总额。同义词全局不重复，重复时静默去重
enName字符串否对应物理字段英文名，用于自动匹配与研发对齐
termType枚举是七类之一，见 2.1。创建后变更类型需重新校验已存在的挂载关系
2 作用域 scope.models字符串数组是 生效的模型（业务场景）。空数组表示不限场景，仅管理员可置空
scope.tables字符串数组否生效的物理表。空表示模型内全部表。存在表名跨模型重名，存储时需与 models 联合表述
scope.fields字符串数组否仅 measure / dimension / time 类型可填，用于限定可承载该口径的字段
3 计算规格 agg枚举measure 必填 SUM / COUNT / COUNT_DISTINCT / AVG / MAX / MIN / NONE。默认 NONE 表示该字段已是汇总值，不可再聚合
unit枚举measure 必填 元 / 万元 / 个 / 平方米 / % 等。用于答案单位换算与量纲校验
precision整数 0–6否小数位，默认 2。比率类默认 4
taxIncluded布尔measure 必填 是否含税。含税与不含税必须定义为两个独立术语并置于同一互斥组
direction枚举否正向 / 负向。负向术语在增长率类问句中参与符号处理
4 时间口径 timeRole枚举time 必填 业务发生 / 统计期间 / 签订 / 确收 / 记账。同一事实表常有多个日期列，该字段决定默认用哪一个
timeGrain枚举time 必填日 / 月 / 季 / 年。与物理字段粒度一致，不一致时需声明换算规则（待确认）
5 限定条件 predefinedFilter结构化数组否 格式为 [{field, op, value}]，不存裸 SQL 字符串。理由：可跨数据源渲染、可做字段级校验、避免注入。示例：[{field:"status", op:"=", value:"生效"}]
filterPolicy枚举否 强制 / 默认 / 可选。强制：问数每次必须带上，仅当用户明确说「含作废」时才可去除；默认：默认带、可被用户改写；可选：仅作为理解提示，不自动拼入查询
6 值域 valueMapping结构化数组dimension 建议必填 格式为 [{userTerm, field, op, value}]。示例：华东 → {field:"org_code", op:"prefix", value:"31"}。支持层级（区域 > 省 > 市）
hierarchy结构化否维度层级关系，用于「按区域汇总」自动上卷
7 样例 examples结构化数组是（≥1 条） 每条含问句与期望槽位。用于挂载后的回归自测，也作为问数召回的训练样例
negativeExamples字符串数组否不该命中的问句，用于防止过度召回
8 治理 status枚举是草稿 / 待审 / 已上线 / 已下线。仅「已上线」可用于正式问数
exclusiveGroup字符串否 互斥组标识。同组内同一目标只允许挂一个，如「含税 / 不含税」「合同额 / 目标额」
owner / steward用户是责任人，用于冲突告警的推送对象
version整数是定义变更时自增，并写入审计日志。历史问数结果不回写
9 展示 description富文本是 业务定义、计算说明、已知例外。不作为问数推理依据，仅供人读

2.3 四层挂载模型

四层解决四个不同问题，不要求全部挂满。按对问数的价值排序，指标层最高（预制的可复用口径，直接取公式），字段层次之（口径的真正来源），模型层用于场景路由，表层用于 Join 选边与消歧。

层级关系语义回答什么问题基数挂载建议
模型 model划定场景语境这个业务场景在说什么业务1 主 + N 辅只挂 1 个场景主术语（entity 类型），辅术语用于声明场景涉及的其他业务对象
表 table扮演角色这张表是事实还是维表，代表哪个业务对象1 主事实表挂 fact，维表挂 entity。各 1 个即可，不贪多
字段 field口径承载这个字段落的是哪条口径1 主 + N 辅度量、全部时间字段、关键维度必挂。辅术语仅用于限定（如「不含税」）
指标 metric定义引用这个指标的定义从哪来1 主已有指标全部挂。指标是问数的最优路径，价值高于表层

2.4 挂载即配置

关键设计判断：挂载记录必须携带规格，而不只是术语引用。 原因是同一个物理字段在不同场景的用法不同——contract_amt 在收入确认场景按 SUM、不含税统计，在合同数量统计场景中根本不参与聚合。术语给出的是业务定义，规格给出的是「在该场景下的用法」，两者必须分层存储。

{
  target: "field:合同收入确认模型|dwd_contract|contract_amt",
  termId: "t-contract-amt",
  role: "primary",                 // primary | secondary
  source: "manual",                // manual | auto | import
  status: "active",                // active | stale | orphan
  spec: {
    agg: "SUM",
    unit: "元",
    precision: 2,
    taxIncluded: false,
    timeField: "stat_month",
    predefinedFilter: [{ field: "status", op: "=", value: "生效" }]
  },
  mountedBy: "u-1024",
  mountedAt: "2026-10-21T10:00:00+08:00"
}

目标标识规则：model:模型名、table:模型名|物理表名、field:模型名|物理表名|字段英文名、metric:指标ID。必须带模型名前缀，因为同一物理表可能被多个场景引用，且现有字段术语键「模型名|字段名」缺少表层，多表同名字段会互相覆盖。

存储：新增 biz-modeling-term-mounts-v2 统一存放四层挂载。旧的 biz-modeling-field-terms-v1 与 metric.termIds 首次加载时迁移为 v2 记录（role 置 primary、spec 留空并在列表标「规格缺失」），迁移后旧键保留只读，不删除。

2.5 继承规则

模型层术语只向下继承语境，不继承口径定义。模型挂「合同收入」意味着场景内所有表和字段处于该语境，但不能因此推断某字段就是「合同成本」——字段口径永远由字段自身的 primary 术语声明。这条规则是四层不冲突的前提。

由此派生两条实践规则：

1. 问数路由先用模型层主术语锁定场景，再用字段层主术语锁定口径，两级不可互相替代。

2. 字段层缺失 primary 时，不向上取模型术语作为兜底口径，而是标记该字段「不可问数」，避免生成看似合理实则错误的结果。

3. 智能问数查询链路

前两章定义了术语如何绑定资产。本章定义绑定好的语义如何被问数引擎消费：挂载网在引擎里是一张语义图，查询过程就是在这张图上的六步导航。每一步都依赖某一层绑定，也都能指出「缺了哪层绑定会退化成什么行为」。

3.1 五类绑定在链路中的位置

绑定消费步骤作用缺失时的退化行为
模型（场景）第 2 步 场景路由把查询空间从全库收缩到一个业务场景，同时作为问数入口的场景检索键全库范围内找字段，召回慢、歧义大，跨场景口径混用
对象（表）第 4 步 Join 规划区分事实对象与维表对象，决定以哪张表为中心展开 Join 链Join 路径靠猜，可能选错中心表导致数值翻倍或丢数
字段第 3 步 槽位装配度量、时间、条件槽位的落点与计算规格来源聚合方式、时间列、隐含过滤全部靠猜，四类失败模式（见 1.2）必然出现
指标第 3 步（短路）命中即取预制口径（公式、默认维度、默认时间），跳过临时推理每个涉及计算的问句都退化为字段级推理，错误率显著上升
维度第 3 步 槽位装配提供分组轴、层级上卷与枚举值转换group by 字段靠猜，用户说的「华东」无法转换为过滤值

3.2 六步流水线

步骤输入处理输出依赖的绑定
1 术语召回用户问句名称精确、同义词、示例问法三路匹配，合并去重候选术语集（每项带类型与匹配来源）术语标识组
2 场景路由候选术语集挂载反查得到模型集合；多于一个时用问句中的实体词与模型主术语比对消歧唯一业务场景（模型）模型层挂载
3 槽位装配场景 + 问句槽位指标命中则短路；否则装配度量/维度/时间/条件四槽，见 3.3字段 + 计算规格字段、指标、维度挂载
4 Join 规划涉及的字段集合同一对象内直接取；跨对象时以事实对象为中心，沿已配置的 Join 关系走最短链跨对象取数路径对象层挂载 + Join 配置
5 组装校验槽位 + 路径聚合、过滤合并（filterPolicy）、时间区间、行级权限、量纲一致性、指标-字段口径一致性（复用第 5 章规则）可执行 SQL + 校验结果spec + 权限模块
6 执行回答SQL执行、按单位与精度格式化、生成槽位溯源解释（每个槽位来自哪个术语与挂载）答案 + 置信度 + 溯源—

3.3 槽位装配规则

槽位装配规则示例
度量 度量术语 → 该场景内 primary 字段挂载 → 取字段与 spec。规格优先级：挂载覆盖 spec > 术语默认 spec；两者皆缺则该槽位标「规格缺失」，问数降级处理 「合同额」→ contract_amt，SUM / 元 / 不含税
维度 维度术语 → 维度引用（共享维）或字段级维度术语 → group by 字段；用户说的枚举值经 valueMapping 转换为过滤条件；出现层级词（如「按省」）时沿 hierarchy 上卷 「华东」→ org_code 前缀 31；「按区域汇总」→ group by 区域维度
时间 时间术语 → 按 timeRole 选定日期列（一表多列时以 role 定列）→ 按 timeGrain 将「上个月」等相对时间解析为区间 「上个月」→ stat_month = 2026-09（确收月，非签订日期）
条件 条件术语 → predefinedFilter 按 filterPolicy 合并进 where；与用户显式条件冲突时用户优先，并在答案中提示「已按你的要求忽略默认条件」 「有效」→ status = '生效'（默认强制）
指标短路 问句命中指标术语 → 直接取指标定义（公式、默认维度、默认时间口径），跳过度量槽推理，仅叠加用户额外条件与额外维度。公式引用的字段仍走第 4 步 Join 规划 「收入达成率」→ 直接取指标公式，不再推理 confirm_amt / target_amt

3.4 维度绑定的两种形态

「维度可以绑定」有两种实现，本方案建议 B 为主、A 为兜底：

形态做法优点缺点
A 字段级维度维度作为术语类型直接挂在字段上，每个字段独立维护值域实现简单，与字段挂载机制一致同一「区域」维度被 10 个对象引用时要定义 10 次；层级与值域分散，口径漂移
B 共享维度（建议）维度作为独立语义资产，维护层级、值域、默认排序；字段挂载一条「维度引用」（target 新增 dimension:维度ID 类型）定义一次处处引用；层级上卷与枚举转换集中维护；跨场景天然一致需新增一种资产类型与引用关系

采用形态 B 后，挂载 target 共五种：model:、table:（对象）、field:、metric:、dimension:。第 2 章的存储结构与校验规则全部适用，维度资产复用术语卡的标识、治理、值域三组字段。

3.5 消歧与降级

情况处理规则用户可感知表现
术语在同一场景内有多个字段落点优先 primary 挂载 → 按近 30 天被问频次 → 仍无法确定则反问反问卡片列出候选字段及其术语口径
术语被多个场景引用第 2 步用问句中的实体词与各场景主术语比对；仍无法消歧则反问「你要看合同收入确认还是分包结算口径的合同额？」
术语无挂载或未上线降级为字段名/注释模糊匹配，答案标注低置信度，不计入命中率统计答案卡片显示「该词尚未接入语义模型，结果仅供参考」
维度值未命中 valueMapping给出相近枚举建议，不猜测「未找到『华南大区』，最接近的是：华南、南区」
问句出现两个度量槽拆为多指标问句或反问；不自行合并「已分别计算合同额与确收金额」
用户改选术语记录 query_term_override 埋点，反哺同义词与示例问法维护改选后本次答案立即按新口径重算

4. 详细方案

一级模块二级功能落地页面描述
术语卡 类型选择与校验 术语创建/编辑抽屉（沿用现有，新增字段）

1. 【页面元素】表单顶部新增「术语类型」单选组，七类并列，随类型变化动态显示后续分组。类型说明以灰字显示在选项下方，如「度量：可聚合的数值口径，必填聚合方式与单位」。

2. 【交互说明】选择类型 → 下方规格分组按 2.1 的类型必填规格自动展开并标红星；切换到不兼容类型（如字段已挂载后改为实体）→ 弹窗提示「已存在 3 处字段挂载，改为实体后这些挂载将失效」，提供「先解绑」与「取消」。

3. 【功能逻辑】必填项未填时保存按钮置灰，并在按钮旁显示缺项数量。同义词输入支持逗号、顿号、回车三种分隔，粘贴多值时自动拆分去重。

4. 【数据字典】见 2.2，字段长度与取值以该表为唯一口径。

5. 【边界说明】名称在同库重复时拒绝保存并高亮名称框；跨库同名允许保存，但显示黄色提示「财务库已有同名术语，请确认是否为同一口径」。同义词与既有术语同义词重复时静默去重，仅提示去除条数。

6. 【验收预期】给定新建一个 measure 类型术语，当聚合方式与单位未填时，保存按钮置灰且提示「还需填写 2 项」；填写完成后保存成功，术语详情页「问数可用性」显示 4 项中已满足 4 项。
限定条件编辑器 术语抽屉 → 限定条件分组

1. 【页面元素】结构化条件行：字段选择器、操作符下拉（等于/不等于/包含/前缀/区间）、值输入框、删除按钮；底部「添加条件」。

2. 【交互说明】点击添加 → 新增空行，字段选择器仅列出该术语作用域内的字段；选择字段后操作符按字段类型过滤（数值字段不出现「前缀」）。

3. 【功能逻辑】不提供裸 SQL 输入入口。若历史数据中存在 SQL 字符串，迁移时尝试解析为结构化条件，解析失败的保留原文并标「需人工确认」。

4. 【边界说明】值为空时该行标红且不允许保存；条件行数为 0 时视为无条件，展示为「无」而非空白。

5. 【验收预期】给定为「有效合同额」添加条件 status 等于 生效，保存后该术语的问数预览中自动带上该过滤条件；删除该行后预览中的条件同步消失。
示例问法维护 术语抽屉 → 示例分组

1. 【页面元素】示例列表，每条含问句输入框与「解析结果」只读展示；底部「添加示例」。

2. 【交互说明】输入问句后点击「试解析」→ 展示该问句命中的槽位（时间/维度/度量/过滤）及对应字段；未命中任何槽位时提示「该问句未命中本术语」。

3. 【功能逻辑】至少 1 条示例为保存前置条件。示例问句同时作为回归测试集，术语定义变更后需重新跑通。

4. 【边界说明】「试解析」为本地规则模拟，标注「模拟结果」字样，不代表真实问数引擎输出。

5. 【验收预期】给定示例问句「上个月华东合同额」，点击试解析后展示 4 个槽位；若删除时间口径，则该问句的时间槽位显示为未命中。
问数可用性面板 术语详情页（现有页新增区块）

1. 【页面元素】五要素检查清单（落点、聚合、单位、时间口径、过滤/值域），每项显示已满足/缺失；顶部一个总体状态标签：可问数 / 部分可用 / 不可问数。

2. 【交互说明】点击缺失项 → 直接定位到编辑抽屉对应分组并聚焦该输入框。

3. 【功能逻辑】必查要素按 termType 决定：measure 查落点、聚合、单位、时间口径；dimension 查落点、值域；time 查落点、粒度；其余类型仅查落点。要素齐备且状态为已上线，方可问数。

4. 【数据与内容规则】「可问数」不仅取决于术语自身，还需存在 active 状态的挂载关系；仅有术语无挂载时显示「未挂载到任何资产」。

5. 【验收预期】给定一个 measure 术语缺少默认时间口径，详情页显示「3/4 项满足，缺少时间口径」，总体标签为「部分可用」，且该术语关联字段的列表就绪度同步降级。
挂载抽屉 层级切换与术语选择 挂载抽屉（改造现有批量挂载抽屉）

1. 【页面元素】顶部四个层级 Tab：模型 / 表 / 字段 / 指标，不可用的层级置灰并注明原因（如「当前为字段视图，模型层请在模型详情挂载」）。左侧术语列表，每项显示名称、类型标签、主辅标识。右侧为规格表单与就绪度实时预览。

2. 【交互说明】切换层级 → 术语列表按「类型与该层级匹配」过滤；点选术语 → 左侧该项标记为选中，右侧规格表单按术语类型展开；首个选中项自动设为 primary，再选第二项时自动降级为 secondary 并显示说明。

3. 【功能逻辑】排序默认按「近 30 天该字段被问次数」降序，无问数数据时按自动匹配得分降序。搜索支持名称、同义词、英文名三类命中，命中同义词时在结果项上显示「匹配：合同金额」。

4. 【边界说明】术语状态非已上线时显示为可选但置灰，hover 提示「该术语待审核，挂载后暂不参与问数」。作用域不覆盖当前目标的术语默认不在列表中，需通过「显示全部」开关查看，选中时提供「扩展该术语生效范围」快捷操作。

5. 【验收预期】给定在字段层抽屉搜索「合同」，结果按被问次数排序；勾选第一个后右侧展开聚合方式选择器；再勾选第二个，第一个保持 primary、第二个显示 secondary 标签。
规格覆盖编辑 挂载抽屉 → 右侧规格区

1. 【页面元素】规格表单：聚合方式、单位、精度、含税、默认时间字段（下拉列出该表全部时间字段）、附加过滤（结构化条件行）；顶部开关「沿用术语默认规格 / 为本目标单独设置」。

2. 【交互说明】默认沿用术语默认规格并只读展示；切换到单独设置 → 表单可编辑，已填值以术语默认值预填；点击「恢复默认」→ 清空覆盖值回到只读。

3. 【功能逻辑】覆盖值与术语默认值不同时，在该字段行显示「规格已覆盖」角标，hover 展示差异对比。覆盖不修改术语本身，不影响其他目标。

4. 【边界说明】时间字段下拉为空（该表无时间字段）时，默认时间口径项显示「该表无可选时间字段」并阻断保存 measure 类挂载。

5. 【验收预期】给定某字段挂载「合同额」并将聚合方式从 SUM 覆盖为 MAX，保存后该字段行显示「规格已覆盖」，术语详情页的默认规格仍为 SUM。
保存前冲突预检 挂载抽屉 → 底部提示区

1. 【页面元素】保存按钮上方三色提示区：红色阻断项、黄色提示项、灰色自动处理项。

2. 【交互说明】每次选择变化即实时预检 → 提示区同步刷新；存在红色项时保存按钮置灰，点击提示区红项可定位到具体冲突。

3. 【功能逻辑】规则见 5.1。红色项阻断保存，黄色项可保存但记录审计，灰色项自动处理不打扰。

4. 【验收预期】给定字段已挂「合同额」，再挂同一互斥组的「目标额」时出现红色项「与已挂载的合同额互斥」，保存按钮置灰。
列表展示 字段级问数就绪度列 模型编辑视图 → 字段设置表（现有表新增列）

1. 【页面元素】新增「问数就绪度」列，以 5 格点阵展示（落点/聚合/单位/时间/过滤），实心为满足。列宽约 90px，不足时折行显示为「4/5」+ 缺口图标。

2. 【交互说明】hover 点阵 → 气泡列出五项各自状态；点击 → 打开该字段挂载抽屉并定位首个缺口项。

3. 【功能逻辑】就绪度由「是否挂 primary 术语」与「该术语按类型的必填规格是否齐备」共同计算，仅挂载无规格记为 1/5（仅落点满足）。

4. 【数据与内容规则】未挂术语显示为空点阵 + 「未挂载」文字，不显示 0/5，避免与「挂了但不全」混淆。

5. 【验收预期】给定字段已挂「合同额」但未填时间口径，该列显示 4 格实心，hover 显示「缺少：时间口径」。
模型与表的术语展示 模型列表、模型头、表卡片、Join 画布表节点

1. 【页面元素】模型列表新增「业务术语」列，展示主术语 chip + 辅术语数量；模型头显示主术语 chip 与其类型标签；表卡片与 Join 画布节点右上角显示小号术语 chip，事实表用实心、维表用描边以区分。

2. 【交互说明】点击 chip → 打开术语详情侧滑；点击 chip 上的「+」→ 打开该层级的挂载抽屉。

3. 【功能逻辑】chip 上展示的是该目标自身的挂载，不展示从模型继承来的术语，避免「字段看起来挂了但实际没挂」的误解。

4. 【边界说明】未挂载时显示虚线框「+ 挂载术语」，点击进入抽屉；无权限时显示为只读文本。

5. 【验收预期】给定模型挂载主术语「合同收入」，模型列表该行显示该 chip；从其下某字段行查看，该字段不显示该 chip。
术语详情反查四分组 术语详情页「关联资产」（现有分组扩展）

1. 【页面元素】由现有「字段 / 指标」两组扩展为「模型 / 表 / 字段 / 指标」四组，每组显示数量，组内列出名称、主辅角色、挂载来源（自动/手动/导入）、挂载时间。

2. 【交互说明】点击组内条目 → 跳转到对应资产并高亮；组内为空时显示「暂无，去挂载」。

3. 【功能逻辑】反查依据 v2 挂载表，不再从 term.modelNames 反推。这样血缘图谱中的 model-term 边可改为真实挂载边（当前为反推的假定边）。

4. 【验收预期】给定术语被 2 个字段、1 个指标挂载，详情页字段组显示 2 条、指标组显示 1 条、模型与表组显示「暂无」。
一致性与度量 指标-字段口径一致性校验 指标编辑页、批量校验入口

1. 【页面元素】指标编辑页公式区下方新增口径校验条，显示指标主术语、公式引用字段的主术语、是否一致三项。

2. 【交互说明】公式或术语变化即触发校验；不一致时显示黄色条「指标挂载「目标额」，但公式引用的 contract_amt 主术语为「合同额」」，提供「改指标术语」「改字段术语」「声明为派生（忽略）」三个操作。

3. 【功能逻辑】「声明为派生」写入一条例外记录，需填写理由，列入季度复核清单。不做静默通过。

4. 【边界说明】公式跨多表引用多个字段时，逐一比对；任一处不一致即提示，全部一致才显示通过。

5. 【验收预期】给定指标主术语为「目标额」、公式引用字段主术语为「合同额」，保存时出现黄色提示且不阻断；点击「声明为派生」并填写理由后可保存，指标详情显示派生标记。
覆盖率看板 语义模型首页 / 术语中心顶部

1. 【页面元素】三个指标卡：术语就绪率、已上线术语数、近 30 天口径纠正次数；下方按模型列出覆盖率条形图。

2. 【功能逻辑】就绪率分母为近 30 天问数涉及的字段集合，非全量字段。无问数日志接入时，分母退化为「已挂载术语的字段数」，并在卡片上标注「按已挂载范围计算，未接入问数日志」。

3. 【边界说明】分母为 0 时显示「暂无数据」而非 0%。

4. 【验收预期】给定某模型 10 个字段被问及、其中 7 个就绪，该模型覆盖率显示 70%。
冲突清单与处置 术语中心 → 冲突治理（新增）

1. 【页面元素】按类型分组的冲突列表：多主术语、互斥组冲突、层级越界、指标口径不一致、孤儿挂载（字段或表已删除）、跨模型同表语义不一致。每条含涉及资产、最近修改人、建议动作。

2. 【交互说明】点击条目 → 展开对比视图（左术语右字段/指标）；提供「一键采纳建议」「标记忽略」。

3. 【功能逻辑】冲突每日定时扫描，结果写入审计。历史多主数据按 mountedAt 最早者保留为 primary，其余置为 secondary 并打冲突标记。

4. 【验收预期】给定某字段历史上挂了两个 primary，扫描后该字段出现在「多主术语」清单，处置后保留一个 primary。

6. 异常与边界

场景处理
术语改名termId 不变，挂载不受影响。FQN 变更写入审计，外部引用的 FQN 需人工核对（待确认是否有外部系统按 FQN 引用）
术语删除存在 active 挂载时禁止直接删除，需先解绑或改为下线。下线为推荐路径
历史数据无 spec迁移后标记「规格缺失」，字段就绪度按 1/5 计算，进入待补清单，不阻断问数但排序靠后

同表被多模型引用允许各自挂载不同术语（场景语境不同），但进入跨模型一致性清单
时间粒度与物理字段不一致暂按物理字段粒度使用，换算规则待确认，不做自动聚合
指标公式跨多表逐字段比对主术语；任一不一致即提示，不因多数一致而放过
无问数日志覆盖率退化为按已挂载范围计算，排序退化为自动匹配得分，页面明确标注数据来源
术语循环引用指标口径类术语引用其他指标时禁止成环，保存时做环检测
